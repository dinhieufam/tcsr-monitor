1. Executive Summary

Paper objective. The paper argues that surgical segmentation systems need a lightweight, model-agnostic safety monitor that detects silent segmentation failures under acquisition degradation, validates that the monitor learns failure rather than corruption fingerprints, and calibrates alarms so missed failures are controlled across clinically relevant groups.

Current maturity. The research idea, method implementation, draft manuscript, and initial experiments are already substantial. Existing evidence includes clean-test AUROC at two IoU thresholds, a four-protocol generalization hierarchy, leave-one-corruption-out robustness, circularity control within corrupted frames, Mondrian group-conditional conformal calibration, SAM2 transfer, and three-seed stability.

Publication risk. The largest remaining risk is not that the system lacks results; it is that reviewers may judge the evidence incomplete. The draft proves that the full system works, but it does not yet fully prove why the specific feature design is necessary, whether the baseline comparisons are fair, and what deployment alarm cost accompanies the safety gains.

Experimental priority. The project should now prioritize high-impact, low-cost experiments that close likely reviewer objections: feature-family ablation, proper baseline cleanup, learned confidence-only baseline, AUPRC reporting, and operational alarm-rate reporting. Expensive external validity experiments should be treated as stretch items only if submission time remains.

Decision Principle Implication for This Project
Think like a MICCAI Area Chair Prefer experiments that directly answer reviewer doubts about validity, fairness, imbalance, reproducibility, and generalization.
Do not inflate scope Do not add experiments merely because they are interesting. Add them only if they materially improve acceptance probability.
Protect the central narrative Every added result should reinforce the same claim: generalization-aware safety monitoring under acquisition degradation.
Separate must-have from stretch Phase 1 closes obvious reviewer holes. Phase 2 improves robustness of the story. Phase 3 is optional and should not delay submission.

4. Detailed Experiment Cards

E1. Feature-Family Ablation

Motivation

The manuscript claims that shape, temporal, confidence, and image-quality features enable detection of confident failures. Reviewers need evidence that these families are not arbitrary.

Research Question

Which feature families are necessary for clean-test, LOCO, and within-corrupted failure detection?

Hypothesis

Shape and temporal features will explain most of the advantage at τ=0.75, while confidence-only features will fail on confident sub-threshold failures.

Reviewer Criticism Addressed

"The paper reports a 22-feature monitor but does not show which features matter."

Experimental Variables

  • Feature set: all, confidence only, shape only, temporal only, quality only.
  • Drop-one: no confidence, no shape, no temporal, no quality.
  • Combined sets: shape+temporal, confidence+quality, shape+quality.
  • Failure threshold: τ=0.5 and τ=0.75.

Required Datasets

EndoVis 2017 clean and corrupted splits already used in the paper.

Required Cached Outputs

features_all.parquet, corrupted train/test feature caches, failure labels, train/cal/test split files.

Implementation ChangesAdd an ablation runner that selects column groups and retrains/evaluates the monitor using identical splits.
Expected OutputsJSON and CSV summary for each feature set; per-threshold AUROC, AUPRC, CI, and LOCO macro score.
Evaluation MetricsAUROC, AUPRC, bootstrap 95% CI, monitor wins across corruption conditions, optional false alarms per minute.
Statistical TestsPaired bootstrap difference in AUROC/AUPRC between full monitor and ablations; report CI on delta rather than only p-values.
Failure CasesConfidence-only matches full monitor; no family drop changes results; ablation variance too high at τ=0.75.
Success CriteriaFull monitor outperforms confidence-only and entropy at τ=0.75; removing shape or temporal features measurably weakens performance or robustness.
Figures to GenerateCompact grouped bar plot of AUROC/AUPRC by feature family; optional heatmap for feature sets by protocol.
Tables to GenerateMain ablation table with clean test and LOCO macro columns.
Paper Sections AffectedExperiments, Discussion, possibly Method if feature grouping needs clearer description.
Checklist Before ImplementationLock feature-family column mapping; confirm same random seeds and same train/cal/test split; decide whether to report all or only informative ablations.
Checklist After ImplementationVerify no data leakage; inspect CI widths; update result registry; decide which rows fit page budget.
Potential Threats to ValidityCorrelated features across families; tree model can compensate with proxy variables; small positive count on clean τ=0.75.

Worth doing: Yes. This is the highest-value missing experiment because it directly validates the method design.

E2. Baseline Audit and Cleanup

Motivation

Weak or placeholder baselines can damage reviewer trust more than omitting them. The paper must compare against baselines that are either properly implemented or explicitly scoped.

Research Question

Do the reported uncertainty and OOD baselines represent fair, functioning comparators?

Hypothesis

A properly audited baseline table will either preserve the monitor advantage or clarify that certain baseline rows should be removed/downscoped.

Reviewer Criticism Addressed

"Temperature scaling equals entropy and feature-distance OOD is chance because it is not actually implemented."

Experimental Variables

  • Baseline type: max-softmax, entropy, calibrated entropy, TTA variance, temporal heuristic, feature-distance OOD.
  • Score source: probability maps, logits if available, encoder embeddings if available.
  • Evaluation split: clean test and corrupted test.

Required Datasets

Existing EndoVis splits.

Required Cached Outputs

Probability maps, logits if available, TTA variance, optional encoder embeddings, labels, split metadata.

Implementation ChangesAudit baseline runner; implement true temperature scaling if logits are available; implement feature-distance OOD using embeddings or remove row from paper.
Expected OutputsBaseline audit report; corrected baselines.parquet; main comparison metrics with corrected rows.
Evaluation MetricsAUROC, AUPRC, CI, score distribution sanity plots, equivalence checks for duplicate score columns.
Statistical TestsPaired bootstrap monitor-vs-baseline AUROC/AUPRC deltas; sanity check identical-score correlations.
Failure CasesNecessary cached logits/embeddings unavailable; corrected baseline closes the gap; row cannot be implemented fairly within schedule.
Success CriteriaEvery baseline row is defensible, documented, and reproducible. Placeholder baselines are removed or renamed.
Figures to GenerateOptional baseline score calibration/reliability plot; not required for main paper.
Tables to GenerateCorrected main comparison table; supplementary baseline audit table if space allows.
Paper Sections AffectedExperiments primarily; Related Work only if a baseline is removed or reframed.
Checklist Before ImplementationInventory cached logits/embeddings; decide minimum fair baseline set; define removal criteria before seeing results.
Checklist After ImplementationConfirm no all-zero columns; confirm temperature scaling is not accidentally identical to entropy unless explained; update captions.
Potential Threats to ValidityFeature-distance OOD may require implementation choices that are hard to fit in the page budget; calibrated entropy may not be meaningful for failure prediction.

Worth doing: Yes. This is a credibility repair task and should be completed before adding more ambitious experiments.

E3. Learned Confidence-Only Baseline

Motivation

The current comparison can be criticized as supervised XGBoost versus unsupervised scalar scores. A learned confidence-only comparator makes the comparison fairer.

Research Question

Does supervised learning over confidence features alone close the gap to the full monitor?

Hypothesis

Confidence-only learning improves over raw entropy but remains weaker than the full feature monitor, especially at τ=0.75.

Reviewer Criticism Addressed

"The monitor wins because it is trained, not because the feature design is meaningful."

Experimental Variables

  • Input features: confidence family only.
  • Learner: same XGBoost settings as full monitor, plus optional logistic regression for transparency.
  • Protocol: clean test, LOCO, circularity control.

Required Datasets

Existing EndoVis clean and corrupted data.

Required Cached Outputs

Confidence feature columns, labels, split metadata, corrupted feature cache.

Implementation ChangesAdd confidence-only feature selector to ablation runner; reuse monitor training code.
Expected OutputsConfidence-only score files and metrics; comparison against entropy, temperature scaling, and full monitor.
Evaluation MetricsAUROC, AUPRC, CI, false alarms per minute at matched miss-rate.
Statistical TestsPaired bootstrap delta full monitor minus confidence-only; report CI.
Failure CasesConfidence-only performs nearly as well as full monitor; this would weaken the morphological/temporal novelty claim.
Success CriteriaFull monitor has meaningful AUROC/AUPRC gain at τ=0.75 and LOCO; confidence-only remains near entropy on confident failures.
Figures to GenerateSmall comparison bar: entropy, learned confidence-only, full monitor.
Tables to GenerateCan be folded into E1 ablation table.
Paper Sections AffectedExperiments and Discussion.
Checklist Before ImplementationDefine confidence column list; use identical seeds; lock primary metric.
Checklist After ImplementationCheck whether confidence-only row should appear in main table or ablation table; update interpretation.
Potential Threats to ValidityConfidence features may include area fraction or other implicit morphology if column grouping is careless.

Worth doing: Yes. It is inexpensive and strengthens fairness of the comparison.

E4. AUPRC and Prevalence-Aware Reporting

Motivation

Clean-test failures are rare. AUROC is useful, but reviewers may prefer AUPRC for rare-event detection.

Research Question

Does the monitor retain an advantage under precision-recall evaluation?

Hypothesis

The monitor will retain strongest gains at τ=0.75, though absolute AUPRC will reflect low prevalence.

Reviewer Criticism Addressed

"AUROC is misleading under rare failure prevalence."

Experimental Variables

  • Metric: AUROC versus AUPRC.
  • Threshold: τ=0.5 and τ=0.75.
  • Protocol: clean test, LOCO, circularity, SAM2 transfer.

Required Datasets

No new datasets.

Required Cached Outputs

Saved scores and binary labels for all reported comparisons.

Implementation ChangesAdd AUPRC to evaluation summaries and tables; add prevalence row or note.
Expected OutputsUpdated JSON metrics; PR curves; compact AUPRC table.
Evaluation MetricsAUPRC, baseline prevalence, bootstrapped CI.
Statistical TestsBootstrap CI for AUPRC and paired delta versus baselines.
Failure CasesAUPRC low despite high AUROC; must contextualize with prevalence and threshold objective.
Success CriteriaMonitor improves over confidence baselines in AUPRC at τ=0.75 or the paper transparently narrows claims.
Figures to GeneratePR curve for main clean test or supplementary figure.
Tables to GenerateAdd AUPRC columns to main or supplementary comparison table.
Paper Sections AffectedExperiments; possibly Abstract if a new headline number is strong.
Checklist Before ImplementationConfirm score polarity; define positive class as failure; include prevalence.
Checklist After ImplementationCheck CI stability; verify no threshold leakage; update captions to avoid overclaiming.
Potential Threats to ValidityAUPRC is sensitive to prevalence and split choice; comparisons across different test populations require caution.

Worth doing: Yes. Very low cost and likely to satisfy a standard reviewer request.

E5. Alarm-Rate and Risk-Coverage Reporting

Motivation

A safety monitor is only useful if its alarm burden is understandable. Miss-rate alone does not tell clinicians how often the system interrupts.

Research Question

What alarm cost is paid by global versus Mondrian calibration at target miss-rate α=0.10?

Hypothesis

Mondrian calibration will equalize misses across groups while redistributing false alarms. This trade-off can be made explicit and acceptable.

Reviewer Criticism Addressed

"The method meets miss-rate targets but may alarm too often to be deployable."

Experimental Variables

  • Calibration method: global, Mondrian per severity, Mondrian quality tertile.
  • Target miss-rate α: 0.05, 0.10, 0.20 if space allows.
  • Group: severity, quality bin, clean/corrupted status.

Required Datasets

Existing clean and corrupted test sets.

Required Cached Outputs

Monitor scores, labels, thresholds, group assignments, video FPS.

Implementation ChangesExtend conformal evaluation to report false alarm rate, alarms per minute, and risk-coverage curves.
Expected OutputsPer-group miss-rate and alarm-rate table; risk-coverage JSON; optional curve figure.
Evaluation MetricsMiss-rate, false alarm rate on correct frames, alarms/minute, coverage, risk-coverage AUC.
Statistical TestsBootstrap CI for miss-rate and false alarm rate by group; no formal p-value required.
Failure CasesAlarm burden is very high in mild or medium degradation; must frame as safety-cost trade-off.
Success CriteriaPaper can clearly state the miss-rate gain and corresponding alarm cost, avoiding hidden deployment cost.
Figures to GenerateCoverage-risk curve; grouped bar chart miss-rate versus false alarm rate.
Tables to GenerateOperational calibration table with miss-rate, false alarm rate, alarms/minute.
Paper Sections AffectedExperiments, Discussion, Limitations.
Checklist Before ImplementationDefine alarm aggregation rule; decide whether per-frame alarms or event-level alarms are reported; fix FPS conversion.
Checklist After ImplementationReview whether alarm rate is clinically plausible; update limitation wording if necessary.
Potential Threats to ValidityFrame-level alarms overcount sustained events; surgical usability depends on alert aggregation policy not studied here.

Worth doing: Yes. It gives reviewers a deployment-cost view of the safety result.

E6. Learner Ablation

Motivation

The paper should show the result is not brittle to the use of XGBoost.

Research Question

Do simpler or alternative classifiers recover the same failure-monitoring signal from the feature representation?

Hypothesis

Random forest and XGBoost will perform similarly; logistic regression will be weaker but still above confidence baselines, suggesting useful feature signal.

Reviewer Criticism Addressed

"The contribution is just a tuned gradient-boosted classifier."

Experimental Variables

  • Learner: logistic regression, random forest, XGBoost.
  • Feature set: full and confidence-only if time permits.
  • Protocol: clean test and LOCO.

Required Datasets

Existing EndoVis splits.

Required Cached Outputs

Feature tables and labels.

Implementation ChangesUse existing classifier wrappers for logistic regression, random forest, and XGBoost; standardize hyperparameters.
Expected OutputsLearner comparison metrics and model artifacts.
Evaluation MetricsAUROC, AUPRC, CI, training time, optional calibration quality.
Statistical TestsPaired bootstrap delta between XGBoost and alternatives.
Failure CasesOnly XGBoost works; may imply nontrivial hyperparameter dependence.
Success CriteriaAt least one simpler alternative remains competitive, or XGBoost superiority is clear but not overclaimed.
Figures to GenerateOptional compact learner bar plot.
Tables to GenerateSmall supplementary learner ablation table.
Paper Sections AffectedExperiments and Limitations.
Checklist Before ImplementationFix class weighting and random seeds; avoid extensive tuning that creates a new confound.
Checklist After ImplementationDecide whether result belongs in main text or supplementary paragraph.
Potential Threats to ValidityDifferent learners may require different calibration; do not compare heavily tuned versus untuned models unfairly.

Worth doing: Yes if Phase 1 is complete. It is not the first priority, but it is reviewer-useful.

E7. Temporal Leakage and Order Stress Test

Motivation

Temporal features are powerful but invite leakage concerns in video. The paper should demonstrate that temporal history is handled responsibly.

Research Question

Does temporal information improve monitoring without relying on cross-video leakage or unrealistic frame order assumptions?

Hypothesis

Removing temporal features will reduce performance, while shuffled or reset histories will not create artificial gains.

Reviewer Criticism Addressed

"Temporal features may leak sequence identity or exploit adjacent labels."

Experimental Variables

  • Temporal setting: normal per-video history, no temporal features, shuffled order, strict reset at every clip.
  • Evaluation: clean test, corrupted test, LOCO.

Required Datasets

Existing video splits.

Required Cached Outputs

Frame order, video ID, masks, temporal feature cache or recomputation ability.

Implementation ChangesAdd mode to recompute temporal features under shuffled/reset/no-temporal settings or mask temporal columns at training and test time.
Expected OutputsTemporal stress-test metrics and sanity plots.
Evaluation MetricsAUROC, AUPRC, delta versus normal temporal features, CI.
Statistical TestsPaired bootstrap delta normal minus no-temporal; optional permutation sanity check.
Failure CasesShuffled order performs similarly or better; suggests temporal features are not true temporal signal.
Success CriteriaNo-temporal is weaker than full monitor; shuffled/reset controls do not reveal leakage artifacts.
Figures to GenerateTemporal ablation bar plot, possibly merged into E1.
Tables to GenerateTemporal stress-test table with clean and LOCO columns.
Paper Sections AffectedMethod clarification, Experiments, Limitations.
Checklist Before ImplementationVerify video boundary resets; define shuffled control exactly; avoid label-aware operations.
Checklist After ImplementationInspect first-frame behavior; confirm no cross-video previous-mask use.
Potential Threats to ValidityShort four-second sequences limit temporal conclusions; corruption may create framewise rather than temporal failures.

Worth doing: Yes after Phase 1, especially because temporal dependence is already discussed as a limitation.

E8. Second Fine-Tuned Backbone Transfer

Motivation

SAM2 transfer is useful but not the cleanest test of transfer among fine-tuned surgical segmenters. A second fine-tuned model would better support model-agnostic claims.

Research Question

Does a monitor trained on ResNet34-UNet features transfer to another fine-tuned surgical segmentation backbone?

Hypothesis

Transfer will be weaker than same-backbone training but strong enough to show feature portability across fine-tuned segmenters.

Reviewer Criticism Addressed

"SAM2 is not evidence of transfer among deployed fine-tuned surgical models, especially because entropy wins there."

Experimental Variables

  • Target backbone: DeepLabV3+, UNet++, TransUNet, Swin-UNet, or any already trained model.
  • Transfer condition: UNet monitor to second backbone; second-backbone supervised upper bound; entropy baseline.

Required Datasets

EndoVis 2017 with second-backbone predictions.

Required Cached Outputs

Second-backbone probability maps/logits, masks, features, labels.

Implementation ChangesTrain or load second segmenter; run predictions; extract same monitor features; adapt transfer evaluation script.
Expected OutputsTransfer AUROC/AUPRC table, upper-bound monitor, feature-shift summary.
Evaluation MetricsAUROC, AUPRC, transfer efficiency, failure rate, CI, feature-shift magnitudes.
Statistical TestsBootstrap CI for transfer and upper-bound scores; paired comparison versus entropy.
Failure CasesSecond model performance too similar to UNet; failure count too low; training consumes schedule; transfer underperforms entropy badly.
Success CriteriaTransferred monitor recovers at least 80-90% of supervised upper-bound AUROC and improves over entropy in confident-failure regime.
Figures to GenerateTransfer comparison table/plot; feature-shift plot.
Tables to GenerateBackbone transfer table analogous to SAM2 table.
Paper Sections AffectedExperiments, Discussion, Abstract/Conclusion only if very strong.
Checklist Before ImplementationConfirm model availability; estimate failure prevalence before full run; decide no-go threshold after pilot.
Checklist After ImplementationCheck whether result strengthens or complicates narrative; do not bury negative entropy comparison.
Potential Threats to ValidityChanging backbone may change calibration and failure distribution; training quality confounds monitor transfer.

Worth doing: Conditional. High upside, but not worth delaying submission unless cached second-backbone outputs are close to ready.

E9. Cross-Sequence Stress Test

Motivation

The paper uses a fixed sequence split. A sequence-level stress test can reduce concern that the monitor is tuned to a few videos.

Research Question

How stable is monitor performance when the held-out test sequence changes?

Hypothesis

Performance will vary by sequence but remain above confidence baselines on average, especially in corrupted settings with larger sample sizes.

Reviewer Criticism Addressed

"The paper uses only one dataset and one sequence split."

Experimental Variables

  • Split strategy: leave-one-sequence-out or leave-group-of-sequences-out.
  • Training condition: clean only or combined clean+corrupted features.
  • Evaluation: clean and corrupted failure detection.

Required Datasets

EndoVis 2017 sequences 1-10.

Required Cached Outputs

Sequence IDs, feature tables, labels, possibly out-of-fold segmenter predictions.

Implementation ChangesAdd sequence-fold split generator and fold-wise monitor training/evaluation.
Expected OutputsFold-wise AUROC/AUPRC, mean and standard deviation, per-sequence failure prevalence.
Evaluation MetricsAUROC, AUPRC, CI, standard deviation across sequences, prevalence.
Statistical TestsDescriptive fold variability; avoid strong significance claims due to n=10 sequences.
Failure CasesSome sequences have too few failures for stable AUROC; fold estimates may be uninformative.
Success CriteriaAverage performance remains above baselines; sequence variance is transparently reported.
Figures to GeneratePer-sequence performance dot plot.
Tables to GenerateSequence-fold summary table.
Paper Sections AffectedExperiments, Limitations.
Checklist Before ImplementationCheck positive counts per sequence; define folds that avoid zero-positive test sets.
Checklist After ImplementationMark unstable folds; decide whether result is main text or supplementary.
Potential Threats to ValidityEndoVis has only ten short sequences; fold variability may reflect label scarcity more than method weakness.

Worth doing: Maybe. Useful if Phase 1/2 are complete, but not as strong as real cross-dataset validation.

E10. Cross-Dataset Evaluation

Motivation

External validation would address the single-dataset limitation most directly.

Research Question

Does the monitor generalize from EndoVis 2017 to another surgical segmentation dataset?

Hypothesis

If labels and instrument definitions align, the monitor should retain some failure-detection signal, but thresholds will require fresh calibration.

Reviewer Criticism Addressed

"All results are on one dataset and may not generalize clinically."

Experimental Variables

  • Target dataset: CholecSeg8k or another compatible surgical segmentation dataset.
  • Transfer setting: no retraining, monitor retraining, fresh conformal calibration.
  • Segmentation backbone: existing model or dataset-specific fine-tuned model.

Required Datasets

External dataset with compatible binary instrument/tool masks.

Required Cached Outputs

Preprocessed frames, masks, segmenter predictions, feature tables, labels.

Implementation ChangesDataset ingestion, mask harmonization, segmenter inference or retraining, feature extraction, evaluation scripts.
Expected OutputsExternal-dataset AUROC/AUPRC, calibration behavior, failure examples, limitations audit.
Evaluation MetricsAUROC, AUPRC, failure prevalence, miss-rate, false alarms/minute, CI.
Statistical TestsBootstrap CI; no cross-dataset p-value unless paired samples exist.
Failure CasesLabel mismatch; tool definitions not comparable; segmentation backbone not trained; preprocessing consumes schedule.
Success CriteriaExternal validation yields interpretable results without compromising deadline or methodological clarity.
Figures to GenerateExternal failure examples; external performance table.
Tables to GenerateDataset comparison and external validation table.
Paper Sections AffectedExperiments, Discussion, Limitations, possibly Abstract/Conclusion if strong.
Checklist Before ImplementationConfirm legal/data availability; inspect masks; run 20-frame pilot; estimate total time before committing.
Checklist After ImplementationCheck dataset compatibility; avoid overclaiming if task differs from EndoVis.
Potential Threats to ValidityDomain/task mismatch may make negative results uninterpretable; external dataset may not contain comparable robotic instruments.

Worth doing: Not recommended for the current submission unless the external pipeline is already nearly complete.

Recommended Execution Order
